# ADR-003: Контракт результат → рендер → ошибки

- **Статус**: accepted (2026-10-06)
- **Связанные**: ADR-002; спека §10.4, §12.2, §12.4 (F10, F13, N2, N8)

## Контекст

Спека фиксирует: два presenter'а (text/json) над одним use case; JSON — только
в stdout с `schema_version`, прогресс/warnings — в stderr; NDJSON для
follow/watch; закрытый реестр кодов ошибок «code → exit → hint» (§12.4);
ошибка отвечает на 4 вопроса (§12.3). Нужен конкретный механизм, исключающий
расползание форматирования по командам (болезнь v1: каждый модуль печатал сам).

## Решение

1. **Результаты use cases** — frozen dataclasses из `core/models.py`
   (`StatusResult`, `ListResult`, `DeploymentResult`, `ValidationReport`,
   `BackupResult`, `InfoResult`, ...), полные и машиночитаемые; ничего
   «человеческого» внутри.
2. **Рендереры** — `ui/renderers/{text,json,ndjson}.py`, чистые функции
   `render(result) -> RenderedOut(stdout: str, stderr: str)`. Диспетчеризация —
   реестр по типу результата (`dict[type, Renderer]`), регистрируется в
   composition root. Отсутствие рендерера для типа = программная ошибка
   (AssertionError на этапе сборки, не в рантайме пользователя).
3. **JSON**: канонический сериализатор — dataclass → dict (explicit `to_json()`
   на каждом результате, чтобы контролировать схему) + обёртка
   `{"schema_version": 1, ...}`. JSON-ошибка тоже объект с `schema_version`.
4. **Ошибки**: `PlatformError(code, exit_code, message, object, hint, cause)`
   в `core/errors.py`; коды — закрытый реестр §12.4 спеки как константы;
   unexpected-исключение → `internal_error` (exit 1), traceback только при
   `--verbose`. Классификация — в одном месте (`core/errors.py`), CLI-адаптер
   только маппит.
5. **NDJSON**: рендерер `ndjson` применяется только для потоковых команд
   (`logs --follow --json`, `status --watch --json`) — результаты
   соответствующих use cases возвращаются итератором событий.

## Альтернативы

- **Форматировать в use cases** (v1-стиль, print из команд): отвергнуто —
  прямо запрещено F13; воспроизводит вразнобой v1.
- **Рендереры как методы результатов** (`result.render_text()`): отвергнуто —
  тащит rich/ui в домен (нарушение §10.2) и размывает презентацию по моделям.
- **Исключения без кодов + strings**: отвергнуто — скрипты гейтят по типу
  причины (US-C3), реестр §12.4 спеки обязателен.

## Последствия

**Положительные**: единственное место форматирования; JSON-схемы контролируемы
и тестируемы (golden); расширение = результат + 2 рендера + регистрация;
ошибки предсказуемы для CI.

**Отрицательные**: церемония «результат + рендеры» на каждую новую команду
(принято); риск расползания models.py — контролируется ревью (данные без UI).

**Нейтральные**: NDJSON-итераторы требуют, чтобы use cases потоковых команд
были генераторами (совместимо с ADR-001: тики/строки итерируются синхронно).
